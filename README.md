# Twitter Research Agent

Автономный агент, который раз в 4 часа ищет свежие посты в X (Twitter)
по вашим темам и критериям (лайки / просмотры / репосты) и присылает
дайджест в Telegram.

**Работает на GitHub Actions — бесплатно, без сервера, без карты,
ваш ПК может быть выключен.**

## Как это устроено

```
GitHub Actions (cron: каждые 4 часа, runner на ~10 минут)
  ├─ docker: grok2api (шлюз к Grok, поднимается на время прогона)
  │    ▲ SSO-токен вашего аккаунта Grok (из Secrets)
  ├─ python: агент — добавляет SSO в grok2api через admin API,
  │    просит Grok найти посты по темам, фильтрует дубли (state/seen.db),
  │    отправляет отчёт в Telegram
  └─ state/ (настройки + база отправленных) коммитится обратно в репо
```

У Grok есть живой поиск по X — агент использует его через grok2api,
поэтому посты реальные, со ссылками и метриками.

## Запуск: ~15 минут

### 1. Залейте этот проект в GitHub

Создайте репозиторий (например `twitter-research-agent`) и запушьте
содержимое этой папки:

```powershell
cd twitter-research-agent
git init
git add -A
git commit -m "init"
git branch -M main
git remote add origin https://github.com/<ВАШ_ЛОГИН>/twitter-research-agent.git
git push -u origin main
```

> **Public или private?** Public — минуты Actions безлимитные, но темы
> и список отправленных постов будут видны всем. Private — бесплатно
> 2000 минут Actions в месяц; прогон занимает ~8-10 мин × 6 раз в день
> ≈ 1500-1800 мин/мес — впритык, но обычно хватает.

### 2. Соберите секреты

| Секрет | Где взять |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Telegram → **@BotFather** → `/newbot` → токен вида `123456:AA...` |
| `TELEGRAM_CHAT_ID` | Telegram → **@userinfobot** → ваш числовой id |
| `GROK_SSO` | Войдите на https://grok.com → F12 → **Application → Cookies → grok.com** → значение cookie **`sso`** |
| `G2A_JWT_SECRET` | Сгенерируйте: `openssl rand -hex 32` (или любой генератор, 64 hex-символа) |
| `G2A_CRED_KEY` | Сгенерируйте: `openssl rand -base64 32` |
| `G2A_ADMIN_PASSWORD` | Придумайте пароль (латиница + цифры, без спецсимволов) |

> ⚠️ `GROK_SSO` = полный доступ к вашему аккаунту Grok. Храните только
> в GitHub Secrets, никому не показывайте.

### 3. Добавьте секреты в репозиторий

GitHub → ваш репозиторий → **Settings → Secrets and variables → Actions
→ New repository secret** — создайте все 6 секретов из таблицы выше.

### 4. Запустите и проверьте

**Actions → Twitter Research → Run workflow**.

> Если workflow уже запустился сам после пуша и упал из-за отсутствия
> секретов — не страшно, просто запустите заново после шага 3.

Первый прогон (~5-10 мин): поднимет grok2api, импортирует SSO,
спросит у Grok посты по темам из `state/settings.json` и пришлёт
дайджест в Telegram. После успешного прогона workflow будет
срабатывать сам — каждые 4 часа.

Если прогон упал — откройте лог job'а: там логи агента и (при ошибке)
последние 200 строк логов grok2api.

### 5. Настройте темы и критерии

Отредактируйте **`state/settings.json`** прямо в веб-интерфейсе GitHub
(кнопка ✏️) и закоммитьте — изменения подхватятся следующим прогоном,
а коммит этого файла дополнительно запускает тестовый прогон сразу.

```json
{
  "topics": [
    { "name": "AI и нейросети", "query": "LLM, агенты, новые модели" },
    { "name": "Крипта", "query": "bitcoin, ethereum, DeFi, аирдропы" }
  ],
  "min_likes": 50,
  "min_views": 10000,
  "min_reposts": 5,
  "max_posts_per_topic": 5,
  "interval_hours": 4,
  "model": "grok-chat-fast"
}
```

- `topics` — список тем: `name` (заголовок в отчёте) и `query`
  (поисковые ориентиры для Grok, пишите свободно);
- `min_likes` / `min_views` / `min_reposts` — пороги. Пост проходит,
  если набирает **хотя бы один** порог (метрики от модели приблизительны);
- `max_posts_per_topic` — максимум постов по теме за прогон (1-25);
- `model` — модель из grok2api. Для бесплатного аккаунта — `grok-chat-fast`.

Чтобы изменить **интервал**, отредактируйте cron в
`.github/workflows/research.yml` (поле `interval_hours` — для
VPS-варианта). Например, раз в 6 часов: `cron: "17 */6 * * *"`.
Расписание — по UTC; GitHub может запускать с опозданием под нагрузкой.

## Траблшутинг

| Симптом | Причина и решение |
|---|---|
| Job падает с «не заданы переменные окружения» | Не созданы или опечатаны имена секретов (шаг 3) |
| «провижининг: логин админа: HTTP 401» | `G2A_ADMIN_PASSWORD` в секретах отличается от того, что в config — пересоздайте секрет |
| «провижининг: импорт SSO не удался» | `GROK_SSO` протух/неверен — возьмите свежий из cookies (шаг 2) |
| «Ошибка запроса к grok2api: 403» / постоянно пусто | Аккаунт Grok заблокирован или квота исчерпана. Проверьте, что аккаунт жив: зайдите на grok.com |
| «новых постов не найдено» каждый прогон | Снизьте пороги, расширьте `query` темы. Учтите: агент ищет за последние 24 часа и не шлёт повторы |
| Отчёт есть, но метрики странные | Метрики сообщает модель Grok — они приблизительны по своей природе |
| Cloudflare/IP-проблемы у grok2api в runner | Редкий случай: GitHub-раннеры работают из Azure. Если в логах grok2api ошибки Cloudflare — напишите мне, добавим WARP-профиль |

## Вариант B: свой сервер / домашнее железо

Если появится VPS или Raspberry Pi — в репозитории уже лежит
`docker-compose.yml` с двумя сервисами (grok2api + агент-демон с
Telegram-ботом). Там темы и пороги меняются командами бота на лету
(`/addtopic`, `/setlikes`, `/run` и т.д. — полный список по `/help`).

```bash
cp .env.example .env   # заполнить токены
# в grok2api-config.yaml заменить три CHANGE_ME
docker compose up -d --build
```

Демон-режим агента — `agent/app/main.py` (polling + планировщик);
CI-режим для GitHub Actions — `agent/app/ci.py` (один прогон).

## Опционально: пул аккаунтов через grok-register

Если упрётесь в лимиты одного аккаунта Grok, можно нарегистрировать пул
через [grok-register](https://github.com/xinxinshuhao-create/grok-register)
и положить SSO-токены в `GROK_SSO` через перенос строки (импорт grok2api
принимает TXT со списком). Понадобятся платный ключ YesCaptcha (капча),
почтовый провайдер и желательно прокси.

## Дисклеймер

- Использование SSO-токена через grok2api и массовая регистрация аккаунтов
  могут нарушать ToS xAI — аккаунт могут заблокировать. Риск на вас;
  при интервале 4 часа и нескольких темах нагрузка умеренная.
- Не коммитьте секреты в репозиторий. `state/` содержит только настройки
  и список уже отправленных ссылок.
